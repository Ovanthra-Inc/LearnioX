# Phase 5 — Role & Permission Management (RBAC)

This is one of the most important phases.

After this phase, **every API** in your system will be protected by permissions instead of hardcoded checks.

Example:

Instead of

```python
if user == owner:
```

You'll do

```python
if user.has_permission("course.create"):
```

This makes your platform scalable and enterprise-ready.

---

# Goal

Build a complete **Role-Based Access Control (RBAC)** system.

Every institution can create custom roles and assign permissions.

# Validation Rules

Role

* Name required
* Name unique within institution
* Cannot delete Owner role
* System roles cannot be renamed

Permission

* Read-only
* Created by platform
* Cannot be deleted by institutions

Member

* Can have multiple roles
* Duplicate roles not allowed

# Business Rules

* Every institution has its own independent role system.
* Platform permissions are predefined and immutable.
* Institutions can create unlimited custom roles (subject to future plan limits).
* Members can have multiple roles, and their effective permissions are the union of all assigned roles.
* The **Owner** role is a protected system role that cannot be deleted or reassigned.
* Authorization should always be permission-based (e.g., `course.create`) rather than role-name-based (e.g., `Admin`), so roles remain flexible.
* Every protected endpoint in future phases (courses, lessons, storage, analytics, etc.) should use the same permission-checking dependency.
