# Phase 2 — Storage Service (Local Storage)

This phase is responsible for **all file management**.

Nothing in your platform (Course, Institution, Lesson, Avatar, Thumbnail, PDF) should upload files directly.

Everything goes through the Storage Service.

This makes it easy to migrate from **Local Storage → S3/Cloudflare R2/MinIO** later.

---

# Goal

A centralized file management system.

Supported files:

* Images
* Videos
* PDFs
* Documents
* Thumbnails
* Logos
* Banners
* Attachments

# Business Rules

* Every uploaded file gets a UUID-based filename.
* Original filenames are stored only as metadata.
* All uploads go through the Storage Service; no other module writes directly to disk.
* Use soft delete by default; permanent deletion is explicit.
* Maintain file metadata in PostgreSQL.
* Validate MIME type, extension, and file size before saving.
* Organize files into dedicated folders (videos, PDFs, avatars, etc.) to simplify maintenance.
* Future migration to object storage (S3, MinIO, Cloudflare R2) should only require replacing the storage implementation, not changing the rest of the application.

This storage layer becomes the foundation that later phases (Institution, Course, Lesson, Avatar, Thumbnail, Certificates, Attachments) will reuse instead of implementing their own upload logic.
