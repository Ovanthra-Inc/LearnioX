For **LearnioX V1**, this is the tech stack I recommend.

# 1. Frontend Stack

Use one monorepo with separate apps.

```text
apps/
├── web/       # public learner platform
├── studio/    # creator/institution dashboard
└── admin/     # platform admin panel
```

| Layer           | Tech                                             |
| --------------- | ------------------------------------------------ |
| Framework       | **Next.js App Router**                           |
| Language        | TypeScript                                       |
| Styling         | Tailwind CSS                                     |
| UI Components   | shadcn/ui                                        |
| Icons           | Lucide React                                     |
| Animation       | Framer Motion                                    |
| Forms           | React Hook Form + Zod                            |
| Client State    | Zustand or Redux Toolkit                         |
| Server State    | TanStack Query                                   |
| Tables          | TanStack Table                                   |
| Charts          | Recharts                                         |
| Video Player    | Cloudflare Stream Player / custom player wrapper |
| Auth Handling   | HttpOnly cookie-based auth                       |
| Package Manager | pnpm                                             |
| Monorepo Tool   | Turborepo                                        |

Next.js App Router is the right choice because it supports modern layouts, routing, Server Components, Client Components, route handlers, streaming, metadata, and app-level organization. ([Next.js][1])

My recommendation:

```text
Next.js + TypeScript + Tailwind + shadcn/ui + TanStack Query + Zustand
```

Use **Zustand** for lightweight UI state like sidebar state, selected institution, filters, and local dashboard state. Use **TanStack Query** for API data.

# 2. Backend Stack

Every microservice should be FastAPI-based.

| Layer                  | Tech                              |
| ---------------------- | --------------------------------- |
| Framework              | **FastAPI**                       |
| Language               | Python 3.12+                      |
| API Style              | REST                              |
| Validation             | Pydantic v2                       |
| ORM                    | SQLAlchemy 2.0 async              |
| Migration              | Alembic                           |
| DB Driver              | asyncpg                           |
| HTTP Client            | httpx                             |
| Background Jobs        | Celery / Dramatiq / Arq           |
| Internal Service Calls | REST with httpx                   |
| Testing                | Pytest + pytest-asyncio           |
| Dependency Management  | uv or Poetry                      |
| API Docs               | OpenAPI auto-generated by FastAPI |

FastAPI is production-ready, type-hint-based, and designed for high-performance API development. ([FastAPI][2]) FastAPI also works well with SQL databases, and its docs commonly show SQLModel/SQLAlchemy-style relational database usage. ([FastAPI][3])

My recommendation:

```text
FastAPI + Pydantic v2 + SQLAlchemy 2.0 async + Alembic + PostgreSQL
```

# 3. API Gateway + BFF Stack

Your API Gateway/BFF should also be FastAPI.

| Layer              | Tech                                       |
| ------------------ | ------------------------------------------ |
| Gateway Framework  | FastAPI                                    |
| Reverse Proxy Edge | nginx                                      |
| Internal Routing   | httpx.AsyncClient                          |
| Auth Verification  | JWT introspection / local JWT verification |
| Rate Limit         | Redis                                      |
| Request Tracing    | Correlation ID middleware                  |
| API Composition    | BFF aggregator endpoints                   |
| Config             | pydantic-settings                          |
| Docs               | OpenAPI, but internal routes can be hidden |

Gateway responsibilities:

```text
- Verify user access token
- Forward x-user-id, x-session-id, x-institution-id
- Aggregate data for frontend pages
- Hide internal microservice complexity
- Apply rate limits
- Normalize error responses
- Add request tracing
```

Use this route model:

```text
/api/v1/public/*      → public BFF aggregation
/api/v1/me/*          → learner BFF aggregation
/api/v1/studio/*      → creator dashboard BFF aggregation
/api/v1/admin/*       → admin BFF aggregation
/api/v1/auth/*        → auth service proxy
```

# 5. Video / Media Stack

This is very important because you are building a YouTube-like learning platform.

## Recommended V1 Option

Use **Cloudflare Stream** for video.

| Feature              | Tech                                    |
| -------------------- | --------------------------------------- |
| Video upload         | Cloudflare Stream direct creator upload |
| Video processing     | Cloudflare Stream                       |
| Encoding/transcoding | Cloudflare Stream                       |
| Playback             | Cloudflare Stream Player                |
| CDN delivery         | Cloudflare                              |
| Thumbnails           | Cloudflare Stream                       |
| Subtitles            | Cloudflare Stream / your AI service     |
| Signed playback      | Cloudflare signed URLs / token access   |

Cloudflare Stream handles upload, storage, encoding, and delivery through one API, which is ideal for your V1 because you do not want to build video infrastructure from scratch. ([Cloudflare Docs][4]) It also supports direct creator uploads, so users can upload videos without exposing your API token to the browser. ([Cloudflare Docs][5])

Recommended:

```text
Cloudflare Stream for videos
Cloudflare R2 for PDFs/images/assets
Cloudflare CDN for public assets
```

Alternative:

```text
Mux Video
Bunny Stream
AWS S3 + MediaConvert + CloudFront
Azure Blob + Azure Media Services replacement pipeline
```

For your case, choose **Cloudflare Stream + R2**.

# 8. Authentication Stack

Use your own Auth Service.

| Feature               | Tech                   |
| --------------------- | ---------------------- |
| Password hashing      | Argon2 / bcrypt        |
| Access token          | JWT                    |
| Refresh token         | HttpOnly Secure cookie |
| Token blacklist       | Redis                  |
| Session store         | PostgreSQL + Redis     |
| OAuth                 | Google OAuth           |
| Email verification    | OTP/token              |
| Role auth             | RBAC service           |
| Internal service auth | API keys / mTLS later  |

Recommended auth model:

```text
Access Token:
- Short-lived JWT
- Sent in Authorization header or managed through BFF

Refresh Token:
- Long-lived
- HttpOnly Secure SameSite cookie
- Rotated on refresh
- Stored hashed in DB
```

For your Next.js frontend, prefer cookie-based refresh tokens because middleware/proxy and server components can access cookies more safely than localStorage.
